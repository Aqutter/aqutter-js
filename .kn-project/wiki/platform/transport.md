# 統一傳輸

## Summary
網頁與殼之間只有一條多工的本機 WebSocket 連線，網頁的呼叫、殼的回應、事件與二進位酬載都走這一條。client 在第一次使用時建立連線，連線建立前的呼叫先排隊，斷線後以退避方式自動重連，每次重連都重新讀取殼注入的連線資訊。不在殼內的環境（純瀏覽器、伺服端渲染）不會建立連線，呼叫直接拋錯。

## 運作方式

![連線與重連](transport.連線與重連.svg)

1. 第一次呼叫或訂閱事件時才建立傳輸，之前不會連線。
2. 先判斷是否在殼內：沒有殼注入的連線資訊就不連線。
3. 讀取連線資訊、建立連線，成功後把排隊中的呼叫依序送出。
4. 失敗就等一段時間再試，等待時間每次加倍，有上限，每次重試都重新讀取連線資訊。
5. 連線建立前排隊超過上限時，排隊中的呼叫以無法連到殼的錯誤結束。

### 呼叫與事件

呼叫與事件共用同一條連線，以訊框區分，酬載可以直接帶二進位資料。

1. 呼叫帶著 handler 名稱與酬載送出，殼回應成功結果或結構化的錯誤。
2. 殼回傳錯誤時，client 轉成帶錯誤碼的例外，不分呼叫方是內建功能還是 plugin。
3. 事件由殼主動送來，client 依頻道名稱分派給訂閱者。
4. 連線中斷時，進行中的呼叫以連線已關閉的錯誤結束，重連成功後新的呼叫恢復正常。

來源：1. [transport.ts](../../../src/transport.ts)　2. [frame.ts](../../../src/frame.ts)　3. [error.ts](../../../src/error.ts)

## 規則

| 規則 | 說明 |
|---|---|
| 連線數 | 一個頁面一條，所有呼叫與事件共用 |
| 排隊上限 | 連線建立前的呼叫最多排隊 10 秒 |
| 重連退避 | 從 200 毫秒起每次加倍，上限 5 秒 |
| 連線資訊 | 每次連線前重新讀取，見連線資訊頁 |
| 不在殼內 | 呼叫直接拋錯，傳輸狀態永遠是關閉 |
| 內容安全政策 | 網頁若設了政策，需允許連到本機的 WebSocket，否則連線被靜默擋掉 |
