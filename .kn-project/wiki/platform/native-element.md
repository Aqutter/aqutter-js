# 原生內容元素

## Summary
`<aqutter-native>` 把殼裡的原生內容（例如地圖）放進網頁：元素佔版面，並把網頁的手勢回傳給原生端。顯示有兩種模式：鏡像由原生端擷取畫面、傳到元素裡的畫布；穿透讓原生內容直接畫在透明的 WebView 下面，元素只回報自己的位置與大小。`mode` 屬性選擇（預設 `auto`），兩種模式共用同一組手勢與事件，模式由原生端在每次連線時決定。

## 運作方式

### 模式協商

這張圖回答：元素連上原生端之後，怎麼決定用鏡像還是穿透？

```json diagram id=模式協商
{
  "type": "flow", "dir": "TD", "title": "模式協商", "desc": "連線後第一則訊息送出模式請求，原生端回覆生效的模式；沒回覆就退回鏡像",
  "nodes": [
    {"id": "a", "text": "連上原生端", "kind": "start"},
    {"id": "b", "text": "送出模式請求\n附頁面是否可穿透"},
    {"id": "c", "text": "原生端決定", "kind": "ext"},
    {"id": "d", "text": "穿透", "key": true},
    {"id": "e", "text": "鏡像"},
    {"id": "f", "text": "等待逾時"}
  ],
  "edges": [
    {"from": "a", "to": "b"},
    {"from": "b", "to": "c"},
    {"from": "c", "to": "d", "label": "支援且頁面可穿透"},
    {"from": "c", "to": "e", "label": "其他情況"},
    {"from": "b", "to": "f", "label": "1 秒沒回覆", "kind": "fail"},
    {"from": "f", "to": "e", "label": "舊版原生端"}
  ]
}
```

![模式協商](native-element.模式協商.svg)

1. 元素連上原生端後，第一則訊息是模式請求，帶著屬性值與「頁面是否可穿透」。
2. 原生端依平台、App 端的允許範圍與頁面條件決定，回覆實際生效的模式與原因。
3. 回覆是穿透就拿掉畫布、開始回報矩形；是鏡像就保留畫布、照舊收幀。
4. 1 秒內沒有回覆（舊版原生端）就退回鏡像，原因記為無回覆。
5. 改 `mode` 屬性會重新連線並重新協商。

來源：1. [native.ts](../../../src/nativeview/native.ts)　2. [element.ts](../../../src/nativeview/element.ts)

### 穿透時回報位置

1. 協商成穿透後立刻回報一次元素的矩形，單位是 CSS 像素，原點是 WebView 視窗左上角。
2. 元素大小改變、任何祖先捲動、視窗大小改變、頁面可見性改變時再回報。
3. 每個動畫畫面最多一則，內容與上一則相同就不送。
4. 元素沒渲染、寬或高為 0 或頁面不可見時，回報為不可見。

來源：1. [layout.ts](../../../src/nativeview/layout.ts)

## 規則

| 項目 | 說明 |
|---|---|
| `mode` 屬性 | `auto`（預設）、`mirror`、`passthrough`；不合法的值視為 `auto` 並警告一次 |
| 頁面可穿透 | 元素往上到根元素的每個祖先，背景色不透明度都小於 0.99 且沒有背景圖 |
| 偵測範圍 | 不涵蓋兄弟元素、偽元素、陰影遮罩；明確指定 `passthrough` 不偵測 |
| 手勢 | 兩種模式相同，座標是相對元素的 0 到 1 |
| 事件 | 模式確定後觸發 `aqutter-mode`（模式與原因）；`aqutter-frame` 只在鏡像出現 |
| 觸控 | 元素的 `touch-action` 為 `none`，手指從元素內開始滑動是操作原生內容、不捲動頁面 |
