# 原生內容元素

## Summary
`<aqutter-native>` 把殼裡的原生內容（例如地圖）放進網頁：元素佔版面，並把網頁的手勢回傳給原生端。顯示有兩種模式：鏡像由原生端擷取畫面、傳到元素裡的畫布；穿透讓原生內容直接畫在透明的 WebView 下面，元素只回報自己的位置與大小。`mode` 屬性選擇（預設 `auto`），兩種模式共用同一組手勢與事件，模式由原生端在每次連線時決定。穿透時元素會自動讓出後方的頁面背景：祖先的不透明背景暫時變透明，標了 `data-aqutter-bg` 的底層背景層在元素位置挖洞，離開穿透就還原。

## 運作方式

### 模式協商

這張圖回答：元素連上原生端之後，怎麼決定用鏡像還是穿透？

```json diagram id=模式協商
{
  "type": "flow", "dir": "TD", "title": "模式協商", "desc": "連線後第一則訊息送出模式請求，原生端回覆生效的模式；沒回覆就退回鏡像",
  "nodes": [
    {"id": "a", "text": "連上原生端", "kind": "start"},
    {"id": "b", "text": "送出模式請求\n附頁面是否可穿透"},
    {"id": "c", "text": "原生端決定", "kind": "ext"},
    {"id": "d", "text": "穿透", "key": true},
    {"id": "e", "text": "鏡像"},
    {"id": "f", "text": "等待逾時"}
  ],
  "edges": [
    {"from": "a", "to": "b"},
    {"from": "b", "to": "c"},
    {"from": "c", "to": "d", "label": "支援且頁面可穿透"},
    {"from": "c", "to": "e", "label": "其他情況"},
    {"from": "b", "to": "f", "label": "1 秒沒回覆", "kind": "fail"},
    {"from": "f", "to": "e", "label": "舊版原生端"}
  ]
}
```

![模式協商](native-element.模式協商.svg)

1. 元素連上原生端後，第一則訊息是模式請求，帶著屬性值與「頁面是否可穿透」。
2. 原生端依平台、App 端的允許範圍與頁面條件決定，回覆實際生效的模式與原因。
3. 回覆是穿透就拿掉畫布、開始回報矩形；是鏡像就保留畫布、照舊收幀。
4. 1 秒內沒有回覆（舊版原生端）就退回鏡像，原因記為無回覆。
5. 改 `mode` 屬性會重新連線並重新協商。

來源：1. [native.ts](../../../src/nativeview/native.ts)　2. [element.ts](../../../src/nativeview/element.ts)

### 穿透時回報位置

1. 協商成穿透後立刻回報一次元素的矩形，單位是 CSS 像素，原點是 WebView 視窗左上角。
2. 元素大小改變、任何祖先捲動、視窗大小改變、頁面可見性改變時再回報。
3. 每個動畫畫面最多一則，內容與上一則相同就不送。
4. 元素沒渲染、寬或高為 0 或頁面不可見時，回報為不可見。

來源：1. [layout.ts](../../../src/nativeview/layout.ts)

### 穿透時回報網頁區域（iOS 原生觸控）

iOS 穿透時，觸控落在元素內、且該點網頁沒有要接管的內容，原生端會直接把觸控交給原生 view（比經網頁轉送平順）。原生端需要知道元素內哪些地方是網頁內容，所以 `layout` 訊息多一個 `webRegions`：

1. 只在 iOS 觸控環境（含 iPadOS 回報成 Mac 的情形）取樣與回報；其他環境不帶這個欄位，原生端視為「觸控全部走網頁」。
2. 以 8 CSS 像素為格，格中心呼叫 `document.elementFromPoint`：命中元素本身（含 shadow 內部）或沒命中任何東西算原生，其餘算網頁；所以 `pointer-events`、堆疊順序、不透明覆蓋都照 DOM 語意。沒有 `pointer-events: none` 的裝飾層（例如漸層遮罩）算網頁區域。
3. 同類相鄰格合成矩形，座標相對元素左上角；超過 64 個矩形時改取每個橫帶的外框（網頁區域只會變大），仍超過就用整體外框。視窗外的部分不取樣。
4. 取樣節流：至少間隔 100 毫秒；元素大小、祖先捲動、視窗大小、可見性、`document` 子樹的 DOM／class／style 變動都會讓下一次取樣重做。元素不可見時回報空清單。
5. 沒有 `document.elementFromPoint` 的環境不帶這個欄位。

來源：1. [webRegions.ts](../../../src/nativeview/webRegions.ts)　2. [layout.ts](../../../src/nativeview/layout.ts)

### 穿透時讓出頁面背景

1. 協商成穿透後，元素往上到根元素的每個祖先，不透明的背景色與背景圖暫時改成透明。
2. 頁面上標了 `data-aqutter-bg` 的底層背景層（例如鋪滿畫面的固定層），用遮罩在元素的位置挖洞；洞的圓角取自元素的圓角設定。
3. 洞跟著元素的位置與大小更新，捲動時也一樣。
4. 退回鏡像、斷線或元素移除時，所有改動還原。
5. 元素加上 `keep-background` 屬性就不做這些，頁面自己負責。
6. 同一頁可以有多個穿透元素：同一個標記層上每個元素各有自己的洞，遮罩是整層減去所有洞；祖先背景用引用計數，最後一個元素釋放才還原。
7. 祖先若有不透明背景（例如包著地圖的卡片），背景會被一併清掉，這是必要的副作用；不想要就把地圖放在不帶背景的容器裡。

來源：1. [seeThrough.ts](../../../src/nativeview/seeThrough.ts)　2. [element.ts](../../../src/nativeview/element.ts)

## 規則

| 項目 | 說明 |
|---|---|
| `mode` 屬性 | `auto`（預設）、`mirror`、`passthrough`；不合法的值視為 `auto` 並警告一次 |
| 頁面可穿透 | 預設一律視為可穿透（祖先背景會自動讓出）；加了 `keep-background` 時才偵測：元素往上到根元素的每個祖先，背景色不透明度都小於 0.99 且沒有背景圖 |
| 自動處理的範圍 | 祖先背景，以及標了 `data-aqutter-bg` 的層；不涵蓋沒標記的兄弟元素、偽元素、陰影遮罩 |
| `data-aqutter-bg` | 標在底層背景層上；標記的層不可以是元素的祖先；同頁多個穿透元素共用同一層，每個元素一個洞 |
| `keep-background` | 元素屬性；關閉自動讓出背景，並讓 `auto` 回到偵測頁面條件 |
| 手勢 | 兩種模式相同，座標是相對元素的 0 到 1 |
| 事件 | 模式確定後觸發 `aqutter-mode`（模式與原因）；`aqutter-frame` 只在鏡像出現 |
| 觸控 | 元素的 `touch-action` 為 `none`，手指從元素內開始滑動是操作原生內容、不捲動頁面 |

來源：1. [element.ts](../../../src/nativeview/element.ts)　2. [layout.ts](../../../src/nativeview/layout.ts)　3. [seeThrough.ts](../../../src/nativeview/seeThrough.ts)
